테스트 역할의 Kilo가 `ls -la`와 거부되는 `find`를 동시에 실행하면, 정책 중단으로 끊긴 `ls -la`의 서명된 시작 기록 때문에 `invalidReceipts: 2`로 `BLOCKED`가 됐다. 위험과 조건은 [STATUS.md](STATUS.md)에 있다. macOS 26 arm64, 공식 Node 24.22.2, Apple container 1.6.0.

| 실제 모델 | 실행하지 않음 |

실제 VM 시나리오: 브로커가 VM 실행 중 또는 생성 중에 강제 종료된 경우, 브로커가 살아남아 VM을 직접 지운 경우, 플랫폼 중단 없이 VM이 남은 경우(계속 무효), 병렬 `ls -la`와 거부된 `find`로 CLI를 끝낸 경우. 중단 뒤에는 VM이 남지 않고, 늦게 시작한 브로커는 VM 없이 125로 끝나며, 끊긴 명령의 늦은 쓰기도 일어나지 않았다.

안전 조건을 빌드 결과에서 하나씩 빼 보았고(중단 표시 무시, VM 클라이언트 대기 생략, CLI 종료 미확인 허용, 시작 시각 검사 생략, 모르는 VM 허용), 다섯 경우 모두 테스트가 실패했다.

실행 중 드러난 것: 시작 기록 직후에는 VM이 아직 목록에 없다. 그래서 목록만 비었다고 믿지 않고 `container run` 클라이언트가 끝날 때까지 기다린다.
