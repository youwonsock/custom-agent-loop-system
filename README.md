# Agent Graph Studio

로컬 코딩 CLI를 에이전트 그래프로 연결하는 독립 웹 앱입니다. 브라우저에서 역할과 성공·실패 경로를 편집하고, 내 컴퓨터의 Node.js 워커가 Codex·Claude Code·OpenCode·Kilo를 실행합니다. VS Code나 VSIX는 필요하지 않습니다.

## 시작

Node.js 24 이상과 사용할 코딩 CLI의 설치·인증이 필요합니다.

macOS에서는 프로젝트 폴더의 **Agent Graph Studio.app**을 더블클릭해 실행할 수 있습니다. 실행기가 lockfile·Node 실행 환경·설치된 패키지를 확인하고 필요하면 패키지를 다시 설치한 뒤 빌드하고 브라우저를 엽니다. 동시에 실행해도 프로젝트 초기화는 한 번에 하나씩 진행합니다. 실행기 창의 **종료** 버튼 또는 Cmd+Q로 서버를 종료합니다. 이미 터미널에서 실행한 서버가 있으면 그 서버를 재사용하며, 실행기를 종료해도 기존 서버는 중지하지 않습니다.

앱 실행기를 재생성하려면 macOS에서 Xcode Command Line Tools를 설치하고 `npm run build:launcher:mac`을 실행합니다. 실행기 파일은 소스 프로젝트 폴더와 함께 사용하며 Node.js 런타임을 포함하지 않습니다. 실행 로그는 `~/Library/Logs/AgentGraphStudio/launcher.log`에 기록됩니다.

터미널에서 실행할 때는:

```sh
npm ci
npm start
```

앱은 `http://127.0.0.1:4317`에서 실행되며 브라우저를 엽니다. 브라우저를 닫아도 작업은 계속됩니다. 서버를 종료하려면 터미널에서 Ctrl+C를 누릅니다.

```sh
node dist/src/server/cli.js ui --no-open
node dist/src/server/cli.js ui --port 4320 --root /absolute/path/to/workspace
```

npm 패키지 설치 후에는 `agent-loop ui`로 실행합니다. 기본 저장 영역은 `~/.agent-loop/graph-workspace`입니다. 이전 버전의 설정과 세션은 읽거나 자동 변환하지 않습니다.

새 **자율 웹 제작·검증 프리셋**의 Kilo 실행은 별도 VM 런타임 준비가 필요합니다. 현재 지원 환경은 Apple Silicon macOS 26과 Apple container 1.6.0입니다. `container` 설치 후 소스에서 `npm run sandbox:prepare`를 실행합니다(설치 패키지는 `node dist/src/core/program_io_setup.js`). 최초 이미지 생성에는 네트워크와 8GiB 이상의 여유 공간이 필요합니다. 준비되지 않은 환경은 모델 호출 전에 BLOCKED로 정지합니다. 실행 화면은 실행 전에 이 조건과, Kilo가 아닌 연결에는 각 CLI의 네이티브 샌드박스만 적용된다는 점을 안내합니다. 명령과 자식 프로그램은 네트워크·호스트 홈·소켓을 공유하지 않는 VM에서 실행하며, 공급자 CLI의 인증·통신은 호스트 제어 영역에 남습니다. [설정과 지원 범위](docs/AUTONOMOUS_WORKFLOW.md#kilo-프로그램-내부-io-격리)를 확인하세요.

## 그래프 만들기

등록한 CLI 연결이 없으면 실행 화면에 처음 실행 안내와 연결 등록 화면으로 가는 버튼이 표시됩니다. 설치된 CLI를 자동으로 찾지는 않습니다.

1. 기본 상호검증 루프를 복제하거나 새 그래프를 만듭니다.
2. 노드를 선택해 이름·역할·지침과 실행 유형을 편집합니다.
3. 성공·실패 핸들을 드래그해 연결합니다. 속성 패널의 다음 단계 선택기도 사용할 수 있습니다.
4. CLI 연결 화면에서 서비스 종류, 이름, 실행 파일을 등록하고 대상 프로젝트의 모델을 조회합니다.
5. 그래프의 공통 모델을 선택합니다. 필요한 노드는 공통 설정 사용을 해제하고 다른 연결·모델을 지정합니다.
6. 원래 목표와 대상 프로젝트를 입력하고 그래프를 실행합니다.

노드 유형은 계획·구현·테스트·검토·최종 승인·중단 처리입니다. 첫 버전은 순차 실행과 성공·실패 분기, 순환을 지원합니다. 병렬 실행·합류·범용 조건식은 지원하지 않습니다.

초안은 자동 저장됩니다. 미완성 연결도 저장할 수 있지만 실행 전에는 구조와 모델을 검증합니다. 다른 창에서 같은 그래프를 바꾸면 현재 초안을 보존하고 저장 충돌을 표시합니다. 초안을 새 그래프로 저장하거나 서버 버전을 다시 읽을 수 있습니다. 그래프 JSON 가져오기는 새 ID로 생성합니다.

## 로컬 서비스와 모델

전체 CLI 자동 스캔, 수동 모델 ID 입력, 고정 대체 모델 목록은 없습니다. 사용자가 등록한 연결에서 조회에 성공한 모델만 선택하고 실행합니다.

| 서비스 | 모델 조회 |
|---|---|
| Codex | 로컬 app-server `model/list` |
| Claude Code | 설치된 실행 파일을 지정한 SDK `supportedModels()` |
| OpenCode / Kilo | 로컬 서버 `/provider`의 연결된 공급자 모델 |

조회와 실행은 같은 CLI와 대상 프로젝트를 사용합니다. 실행·재개 전에 모델을 다시 확인합니다. 조회 실패, 인증 필요, 빈 목록, 지원되지 않는 프로토콜은 구분해 표시하며 자동으로 다른 모델을 선택하지 않습니다. 조회 성공이 실제 모델 권한·할당량을 보장하지는 않습니다.

모델의 비용은 네이티브 목록의 명시적인 `isFree` 정보로 구분합니다. 유효한 `isFree: true`가 있어야 무료로 확인하며, 양수 비용이 함께 보고되면 유료를 우선합니다. CLI가 비용 누락을 0으로 채울 수 있으므로 이름의 `free`나 단가 0만으로 무료 처리하지 않습니다. 가격 미확인은 유료와 같은 재시도 한도를 적용합니다. 연결 화면과 시도 기록에서 판정·조회 시각을 확인할 수 있습니다.

복구 가능한 실패는 기존 attempt·시간 한도 안에서 재시도합니다. 한도 소진 후에는 무료로 확인된 모델만 추가 자동 복구를 예약하며, 출력·토큰 사용이 있었어도 허용합니다. 유료·가격 미확인 모델은 멈춥니다. 공급자 잔액·할당량 소진은 유료·가격 미확인 모델을 즉시 일시정지시키며, 일시적인 429/과부하는 일반 재시도 한도를 따릅니다. 무료 모델도 자동 복구 횟수, 그래프 반복 한도와 인증·권한·환경 오류의 대기 조건을 지킵니다. 자동 복구 직전에 무료 여부를 다시 확인하고, 유료·미확인으로 바뀌면 새 모델 호출을 하지 않습니다. 구독·무료 크레딧·실제 청구액을 추정하지 않으며 금액 기준 예산은 제공하지 않습니다. [성공·실패·재시도 조건 전체](docs/EXECUTION_CONDITIONS.md)를 참고하세요.

API 키, MCP, 웹 검색, 스킬, 훅, 플러그인 설정은 해당 CLI에서 관리합니다. 앱은 자격증명이나 도구 설정을 생성·주입하지 않습니다. 역할별 접근 제한과 완료 판정은 오케스트레이터가 관리합니다.

## 실행과 승인

각 실행은 그래프 revision, 모델 지정, CLI 연결 정의를 snapshot으로 저장합니다. 실행 중 라이브러리를 편집해도 해당 세션은 바뀌지 않습니다.

노드는 방문할 때마다 새 방문 ID를 부여받습니다. 순환해서 계획 노드로 돌아오면 새 계획을 생성하고 새 승인을 받습니다. 재시도·승인 대기·재개는 동일 방문을 이어갑니다. 계획 문서는 앱 안에서 전체 내용을 읽고 수정·승인할 수 있으며, 다른 방문이나 이전 문서 revision에 대한 승인 요청은 거부됩니다.

기본 완료 조건은 정상 종료와 assistant 응답 마지막 독립 행 `[PHASE_DONE]`입니다. 자율 구현 역할의 단일 평문 종료 표식은 [제한된 정규화](docs/AUTONOMOUS_WORKFLOW.md)를 지원합니다. 테스트는 `VERDICT: PASS|FAIL|BLOCKED`, 검토·승인은 `APPROVED|REJECTED` 및 고정 `REQ-###` 요구사항 증거를 검사합니다. 프롬프트 echo나 도구 입력은 assistant 완료로 인정하지 않습니다. 검색을 명시한 목표는 실제 완료된 검색 이벤트와 URL 근거가 필요합니다.

테스트의 `PASS`에는 각 요구사항 블록의 `CHECK_COMMAND`와 네이티브 CLI가 실제 완료한 검증 명령의 성공 결과가 필요합니다. `npm test`, `node --test`, pytest 등 직접 실행한 검사 명령을 사용합니다. 로그 읽기·echo·실패를 숨기는 파이프는 인정하지 않습니다. 기록은 attempt와 방문에 저장되며 형식만 고치는 재시도에서 재사용합니다. 후속 구현·계획·테스트·중단 방문, 실패·반려와 관측된 파일 수정은 이전 검증을 무효화합니다. 테스트를 작성·수정한 경우 마지막 수정 이후의 검사만 인정합니다. 검토·승인은 현재 구현의 테스트 PASS 기록이 있어야 통과하며, 해당 역할에서 추가로 실행한 검사가 실패하거나 미완료이면 APPROVED를 인정하지 않습니다. 환경 제약은 같은 방문에서 사용자 해결을 기다립니다. 이전 세션에 없는 기록을 추정해서 채우지 않습니다.

`SUCCESS`에는 모든 필수 요구사항의 충족 증거, 현재 구현의 실제 테스트 PASS, 마지막 최종 승인(`approval`)의 정상 APPROVED가 모두 필요합니다. 구현에서 바로 완료하거나 실패 간선을 완료에 연결한 그래프는 실행을 차단합니다. 기존 snapshot도 종단에서 같은 조건을 검사하며, 근거 누락 시 사유와 함께 `PAUSED`로 보존합니다. 수동 재개로 수정·재검증·최종 승인을 다시 수행할 수 있습니다. 과거 완료 기록은 소급 변경하지 않습니다.

새 자율 프리셋의 `authoredNodeTests`는 `npm test` 계약에 자체 Node 영역 정책을 요구합니다. 컨트롤러·저장·HTTP 같은 경계를 필수 case로 선언하고 실제 assertion, 무결함 대조군, 제품 결함 탐지를 별도 검증합니다. 검토자와 최종 승인자는 자체 테스트 파일과 품질 보고서를 실제로 읽고 모든 영역을 판단해야 합니다. 설정·계약·제한은 [자율 실행 문서](docs/AUTONOMOUS_WORKFLOW.md#자체-node-테스트의-영역별-계약과-독립-검토)에 설명했습니다.

README 등 누락되면 안 되는 제품 파일은 검증 계약의 `requiredFiles`에 경로와 요구사항 ID로 선언합니다. 구현의 완료 응답, 테스트·검토·승인 경계와 성공 종단에서 대상 내부의 비어 있지 않은 일반 파일인지 확인합니다. 구현이 고치고 테스트는 전체 등록 검사를 새로 실행하며, 검토·최종 승인자는 각 산출물을 실제 읽은 기록과 내용으로 판단합니다. 테스트는 문서·제품·자체 검사·설정을 수정하지 않습니다. 파일 존재 확인만으로 내용의 정확성이나 동작을 통과시키지 않습니다. 선택 필드가 없는 기존 계약은 종전 동작을 유지하며, 목표의 모든 파일을 자동 추론하지 않습니다. [필수 파일 계약과 역할별 복구](docs/AUTONOMOUS_WORKFLOW.md#필수-파일-계약과-역할별-복구)를 참고하세요.

Codex 자율 웹 검증은 검증된 CLI **0.162.1**에서 실행별 로컬 HTTP 정책을 사용합니다. 구현·테스트 역할의 localhost/127.0.0.1/::1 서버와 통신을 허용하고 프록시로 외부 목적지를 제한합니다. 전역 설정은 수정하지 않습니다. macOS Chromium 실행에 추가 권한이 필요하면 정확한 필수 검사 명령을 네이티브 자동 검토에 요청하며, 거절되면 BLOCKED로 보존합니다. 실패한 리디렉션 로그는 새로 생성된 소유 파일인지 확인한 뒤 해시와 함께 보존합니다. `listen EPERM` 같은 환경 오류와 구현의 외부 BLOCKED는 제품 수정 반복으로 보내지 않습니다. [실행 권한과 환경 진단](docs/AUTONOMOUS_WORKFLOW.md#codex-로컬-http와-환경-오류-처리)을 확인하세요.

실행 기록은 검사가 실행됐다는 근거입니다. 모델이 작성한 테스트가 목표 전체를 정확히 검사한다는 보장은 없으므로 중요한 산출물은 독립 인수 검사도 수행해야 합니다. 인식하지 못하는 검사 명령은 자동 통과하지 않습니다. 새 자율 프리셋은 소스 해시 재검사와 Kilo VM 격리도 사용하지만, 이 옵션이 없는 기존 그래프에는 같은 프로그램 내부 I/O 차단이 적용되지 않습니다.

샌드박스의 `listen EPERM` 등 환경 제약이나 테스트의 `VERDICT: BLOCKED`는 원인과 함께 `WAITING_USER`로 보존합니다. 자동 구현 반복이나 권한 확대 없이 환경 확인 후 같은 테스트 방문을 수동 재개합니다. 프롬프트 경로 검사는 공백 경로와 HTTP 요청 대상을 구별하며, 모호한 실제 외부 파일 요청에는 `FILE_ACCESS: /absolute/path`를 사용합니다. 실제 접근 제한은 네이티브 CLI 권한으로 집행됩니다.

- `RUNNING`: 진행 중인 워커가 세션을 소유합니다.
- `WAITING_USER`: 계획·경로·인증·모델 설정 등 사용자 결정이 필요합니다.
- `RECOVERING`: 무료로 확인된 모델의 복구 가능한 실패에 대해 추가 복구를 예약합니다.
- `PAUSED`: 실행 예산·수렴 한도를 소진했거나 전역 성공 조건을 충족하지 못했습니다. 확인 후 수동 재개합니다.
- `STOPPED`: 사용자가 명시적으로 중지했습니다.
- `BLOCKED`: 프로세스 종료·소유권을 확인할 수 없어 새 실행을 차단합니다.
- `SUCCESS`: 모든 필수 요구사항·현재 테스트 증거·최종 승인을 통과했습니다.
- `FAILED`: 처리되지 않은 런타임 오류로 실패했습니다.

실행 화면에서 방문·attempt·진행 시각·계획·응답·로그를 확인하고 중지, 중단 분석, 재개를 수행합니다. 읽던 로그는 새 출력이 와도 자동으로 아래로 이동하지 않습니다. 파일 변경·검색·모델 사용 증거는 로그 보존 크기와 별도로 누적합니다.

실행 오류에는 노드와 CLI 연결 이름, 실제 원인이 함께 표시됩니다. 인증 실패는 CLI의 오류 진단으로 판정하며 일반 응답·도구 출력·ID·시간 값은 인증 판정에 사용하지 않습니다. 인증 오류나 응답 미완료로 중단된 QA를 재개하면 같은 방문에서 새 시도를 시작하고 이전 단계와 승인 기록은 유지합니다.

agent-loop init

## 내부 책임과 상태 보존

| 영역 | 책임 |
| --- | --- |
| `src/core/runtime.ts` | 방문 실행 단계(사전 검사 → 시도 전 가드 → 호출 구성 → 감독 실행 → 증거 게이트 → 완료 판정 → 실패 분류); 정지 경로는 `halt()`에 부수효과를 명시 |
| `src/core/run_policy.ts` | 그래프 자동화 플래그와 연결 CLI 조합으로 정해지는 실행 결정 (예: Codex 로컬 HTTP, Kilo 범위·VM 격리) |
| `src/core/session_transitions.ts` | 승인·재개·방문 이동·중지의 상태 변경 규칙; 프로세스와 파일 I/O는 호출자 담당 |
| `src/core/store.ts`, `session_schema.ts` | version 3 해석, 원자 저장·잠금·저장 순번 비교, 변경된 세션 요약 캐시 |
| `src/core/provider_events.ts`, `process_output.ts`, `process_lifecycle.ts` | 네이티브 이벤트 해석, 출력 프레이밍·마스킹, 제한 시간 내 프로세스 종료 |
| `src/shared/session_updates.ts`, `graph_validation.ts` | 세션 순서 비교·병합, 서버/화면 공통 실행 진단 |
| `src/shared/isolation.ts` | 현재 호스트와 그래프 연결 기준의 프로그램 I/O 격리 범위 안내 (실행 화면에 표시) |

세션의 내부 `revision`은 저장할 때 증가하며 오래된 워커 쓰기·지연 이벤트가 최신 상태를 덮어쓰지 못하게 합니다. 선택 필드 없는 기존 stateVersion 3은 계속 읽으며 없는 성공 근거는 만들어 넣지 않습니다. GUI는 `?summary=1` 목록·SSE와 선택 세션의 상세 조회를 사용합니다. 기존 기본 API 응답은 유지됩니다. 화면 전환 시 그래프 초안·연결 입력·계획 편집 상태는 상위 hook에 남습니다.

## 개발과 검증

```sh
npm run verify:platform
npx playwright install chromium
npm run verify:browser

# 개별 검사
npm run format:check
npm run typecheck
npm test
npm run test:tooling
npm run test:e2e
npm run coverage
npm run smoke
npm run pack:check
npm run pack:smoke
```

빌드는 코어와 웹 정적 자산을 함께 생성합니다. 모델 조회와 실행 테스트는 네 CLI의 프로토콜을 구현한 결정적 가짜 CLI를 사용해 모델 비용 없이 검증합니다. 실제 설치된 CLI의 목록 조회도 별도로 검증합니다.

코드 스타일은 Prettier로 통일합니다(`npm run format`). 포맷만 바꾼 커밋은 `.git-blame-ignore-revs`에 등록하며 `git config blame.ignoreRevsFile .git-blame-ignore-revs`로 blame에서 제외합니다. 포맷 전후의 구문 동일성은 `node scripts/check-format-ast.js <기준 revision>`으로 확인합니다.

`test/golden/`은 노드 프롬프트와 CLI 실행 인자·환경을 바이트 단위로 고정합니다. 의도한 변경일 때만 `UPDATE_GOLDEN=1 npm test`로 갱신하고 diff를 검토합니다. invocation 골든은 `win32`/`posix` 계열별로 두며, 해당 계열의 골든이 없으면 그 테스트를 건너뜁니다. 실행 구조와 정지 경로는 [아키텍처](docs/ARCHITECTURE.md)에 정리했습니다.

구현 목표와 실제 증거는 [인수 기준](docs/IMPLEMENTATION_PLAN.md)과 [검증·수정 기록](docs/VERIFICATION.md)에, 끝낸 작업과 남은 과제는 [작업 현황](docs/STATUS.md)에 기록합니다. 세 문서는 개발 기록이므로 npm 패키지에는 포함하지 않습니다. CI는 Windows·Linux·macOS 코어 검사와 Linux 브라우저 시나리오를 수행합니다.

## 자율 제작·검증

라이브러리의 **↻ 자율 제작 그래프**로 계획 자동 선택·제한된 자동 수정·실제 브라우저 검사·최종 승인을 연결할 수 있습니다. 기존 수동 승인 그래프는 그대로 유지합니다. 사용 방법과 준비 조건은 [자율 실행 안내](docs/AUTONOMOUS_WORKFLOW.md)를 확인하세요.
