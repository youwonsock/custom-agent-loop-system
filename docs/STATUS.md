## 남은 과제

### 우선순위 1: 검증 공백

코드를 더 옮기기 전에 먼저 메워야 하는 항목이다.

| 과제 | 현재 상태 | 완료 기준 |
| --- | --- | --- |
| posix invocation 골든 생성 | `test/golden/invocation/`에 `win32`만 있어 Linux·macOS CI는 이 테스트를 건너뛴다. Unix의 CLI 인자·환경 변경은 고정되어 있지 않다 | Mac에서 `UPDATE_GOLDEN=1 npm test`로 생성해 커밋하고, Linux CI에서도 같은 골든이 통과. 다르면 계열을 나눔 |
| macOS CI의 VM 테스트 실행 여부 확인 | macOS 작업은 성공했지만 Apple container VM 테스트가 그 러너에서 실제로 실행되는지 건너뛰는지 로그로 확인하지 못했다 | CI 로그로 실행 여부를 확인해 기록. 건너뛴다면 해당 보장의 검증 위치를 문서에 명시 |

### 우선순위 2: 남은 구조 정리

원래 계획의 4·5단계와 2단계의 남은 부분이다. 모두 동작 변경 없이 진행하며 골든이 같게 유지되어야 한다.

| 과제 | 현재 상태 | 주의점과 완료 기준 |
| --- | --- | --- |
| `invocation.ts`를 CLI별 builder로 분리 | 426행, 400자 초과 4줄(최대 1,443자) | posix 골든 생성 후 진행. Kilo VM 부분은 macOS CI 통과를 병합 조건으로 둠 |
| `prompt.ts`를 역할별 모듈로 분리 | 411행, 400자 초과 27줄(최대 1,023자) | 긴 줄을 템플릿 리터럴 여러 줄로 풀면 개행이 추가되어 모델 입력이 바뀐다. 문자열 연결이나 `join`으로 출력을 그대로 보존 |
| 정책 객체 적용 범위 확대 | `runtime.ts`의 직접 참조는 0곳이지만 `prompt.ts` 12곳 등 코어에 남아 있다(그래프 검증 40곳은 원래 플래그가 맞음). `buildInvocation`의 옵션도 그대로 많다 | `prompt.ts`와 `buildInvocation`이 `runPolicy` 결과를 받도록 변경 |
| 도달하지 않는 정지 분기 제거 | 실패 분류의 고아 프로세스 분기(`runtime.ts`의 `failure`)는 supervisor가 먼저 처리해 도달하지 않는다 | 도달 불가를 증명한 뒤 별도 커밋으로 제거. 다른 정지 경로의 부수효과 차이도 증명된 것만 통일 |
| 테스트 시간 단축 | 전체 약 8~9분, `--test-concurrency=1` 그대로. 파일 분할은 끝났다 | 파일별 시간을 측정한 뒤 병렬화. 1초 단위 watchdog 테스트가 CPU 경합에서 실패하므로 이 테스트를 먼저 분리하거나 순차로 유지 |
| `VERIFICATION.md` 분리 | 636행의 단일 파일, 머신 로컬 경로 21줄. npm 패키지에서는 이미 제외되어 위험은 낮다 | 날짜별 파일로 나누고 머신 경로 정리 |

### 우선순위 3: 사용성

| 과제 | 내용 |
| --- | --- |
| CLI 찾기 제안 | 처음 실행 안내는 있지만 등록은 여전히 수동이다. "자동 스캔 없음" 원칙과 충돌하지 않게 사용자가 요청하고 확인한 경로만 등록 |
| 화면 전환 지연 | 지연 로드되는 화면으로 전환할 때 1~3초 로딩이 보인다 |
| 캔버스 휠 동작 | 그래프 캔버스 위에서 휠을 굴리면 페이지 대신 그래프가 확대·축소된다. 의도한 동작으로 둘지 결정 필요 |

### 별도 결정이 필요한 기능

리팩터링과 섞지 않으며, 착수 여부를 먼저 정한다.

- Linux·Windows용 프로그램 I/O 격리 백엔드. 지금은 macOS 26 + Apple container에서만 강한 격리가 성립하고, 다른 환경에서는 화면 안내만 제공한다.
- 병렬 노드 실행과 금액 기준 예산.
- 문서와 화면의 영어 지원. 지금은 한국어만 제공한다.
