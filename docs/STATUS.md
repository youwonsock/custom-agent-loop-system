## 정책

- **호환.** 이전 버전 데이터와 호환하지 않고 마이그레이션도 두지 않는다(사용자 결정, 2026-11-02). 그래프는 version 2, 세션은 `stateVersion` 4만 읽는다. 읽을 수 없는 세션과 그래프는 목록에서 빠지고 파일은 그대로 남는다.
- **자율 그래프의 검증 계약.** 자율 그래프는 언제나 고정 검증 계약과 JSON 보고를 쓴다(2026-11-03). 계약을 끄는 `automation.verificationContract` 플래그는 없앴고, 저장 그래프에 남은 이 값은 무시하므로, 꺼 두었던 그래프도 계약을 쓴다. 평문 보고는 수동 그래프의 현재 기능이다.

## 남은 위험

- **다른 CLI.** Codex와 Kilo 무료 모델은 작은 시나리오만 `SUCCESS`이고, Kilo의 `tiny-web-tests`는 최종 승인에서 공급자 한도로 멈췄다. OpenCode는 무료 모델로 끝까지 간 적이 없다.
- **금액 한도.** 시도 사이에만 확인하므로 한 시도가 초과할 수 있고, 구독 요금과 다를 수 있다.
- **병렬 작업의 실제 모델 기록은 1회다.** 충돌과 재시작은 자동 테스트만 거쳤다.
- **샌드박스는 터미널을 거부한다.** 프로젝트의 테스트가 직접 PTY를 열면 샌드박스 안에서 실패한다. Claude CLI 안에 `allowPty`가 있지만 `--settings`로는 적용되지 않았다. 앱 자신은 파이프로 대체하므로 이 저장소의 테스트는 샌드박스 안에서 통과한다.
- **Claude 실행의 격리는 선택이다.** 도구 허용 목록은 보안 경계가 아니다. **Claude 명령 VM 실행**을 켜야 VM을 쓴다. 파일 도구는 호스트에서 실행하므로 훅의 경로 검사가 경계이고, 실제 모델로 1회만 돌렸다.
- **Linux 격리는 VM이 아니다.** 호스트 커널을 공유하는 컨테이너이고, 실제 모델로는 돌리지 않았다. CI가 격리 스위트를 직접 실행한다.
- **macOS VM 결과는 자기 신고다.** 호스팅 macOS 실행기는 가상화를 지원하지 않아(`kern.hv_support: 0`) VM 테스트를 CI에서 돌릴 수 없다. `vm-result` 검사가 PR 본문의 `verify:vm N/N @ <head sha>`를 요구하고 `main` 보호가 이 검사 실패 시 병합을 막지만, 숫자 자체는 작성자가 적는다.
- **`nodeTests`는 첫 시도에 통과한다는 보장이 없다.** Claude Haiku 5.5는 최종 표본 10회 모두 복구 없이 `SUCCESS`였지만, 그 직전 표본은 6회 중 5회가 복구를 거쳤고 더 전에는 6회 중 4회만 통과했다. 잠긴 어댑터의 오류는 복구할 수 없어 `BLOCKED`로 끝난다. 어댑터는 실행해 봐야 알 수 있어 잠금 때 검증하지 않는다. Kilo 무료 모델은 이 경로를 통과한 적이 없어, 이 경로와 VM 격리를 함께 지난 실제 실행은 아직 없다.
- **요구사항과 검사의 연결은 모델이 쓴다.** `npm test`처럼 문구에 명시된 경우만 플랫폼이 잡는다. 그 외에는 인수 테스트 작성자와 독립 검토의 책임이다.
- **CI 간헐 실패.** Windows와 macOS 전체 테스트를 각 5회 돌려 실패 0건을 확인했다(실행 `41384096170`, #53 이전 코드, 테스트를 하나씩 돌리던 때). 표본이 작아 재발 가능성은 남아 있다. #39의 Windows 작업이 평소 9분이 아닌 80분이 걸린 실행에서 타이밍 테스트 4개가 실패한 적이 있어, 실행기가 극단적으로 느리면 이런 테스트는 여전히 깨질 수 있다.

## 범위 밖

착수 여부를 따로 정한다.

- Windows용 프로그램 I/O 격리 백엔드. 호스팅 실행기에서 검증할 수 없어 시작하지 않았다. Linux는 Podman 컨테이너로 제공하며 macOS VM보다 경계가 약하다.
- 노드 전체의 병렬 실행. 구현 노드의 병렬 작업만 제공한다.
- 실행 중 사유, 모델 프롬프트, `docs/`의 영어 지원. 화면과 `README.en.md`만 영어를 제공한다.

테스트를 3개씩 동시에 실행해 Windows CI가 6~7분이 됐다(목표 6분 이하는 일부만 충족). 저장 필드 이름은 바꿀 이름을 찾지 못해 그대로 두었다. CLI fixture 3종은 역할이 달라 합치지 않았다.

## 사용자 환경

공식 Node 24.22.2를 `~/.local/opt/node-24`에 설치하고 `~/.zprofile`의 PATH 앞에 두었다. `.git/config`의 빈 `user.name`을 지웠고, 이 저장소의 push는 `gh` 계정을 쓰도록 저장소 설정에만 등록했다. `~/.npm-cache`의 root 소유 캐시는 `_cacache.root-owned-backup`으로 옮겨 두었고, 지우려면 `sudo`가 필요하다.

앱 실행기는 로그인 셸의 `node`를 먼저 쓰고 Homebrew 빌드는 다른 Node 24 이상이 없을 때만 쓴다(PR #24).

## 브랜치와 태그

원격과 로컬에는 `main`만 있고 태그는 없다. 병합한 작업 브랜치는 병합 직후 지운다.

병합할 수 없는 이전 브랜치 2개를 보존하던 로컬 태그(`archive/codex/integrate-dependabot-branches` `9f39ebf`, `archive/codex/security-hotfix-3.4.1` `87f2b2c`)는 사용자 결정으로 2026-11-03에 지웠다. 둘 다 제거된 VS Code 확장 구조의 코드였다. `9f39ebf`는 원격 `refs/pull/7/head`로 아직 받을 수 있고, `87f2b2c`는 원격 참조가 없어, 이 복사본의 Git이 쓰지 않는 객체를 정리하면 복구할 수 없다.
