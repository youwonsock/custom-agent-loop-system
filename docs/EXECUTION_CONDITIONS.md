# 실행 성공·실패·재시도 조건

2026-10-25 기준. 구현: `src/core/completion.ts`, `runtime.ts`, `success_gate.ts`, `verification_evidence.ts`, `graph.ts`, `model_pricing.ts`, `cli_diagnostics.ts`, `agent_attempt_runner.ts`, `src/server/coordinator.ts`, `runtime_defaults.json`.

## 자율 실행 프리셋

새 자율 그래프는 계획 1개 자동 선택, 검증 실패의 구현 재진입(기본 3회), 선택적인 실제 브라우저 증거 강제를 지원한다. 기존 그래프와 명시적인 승인·STOP·접근·비용 한도는 유지한다. 수정 가능한 BLOCKED는 명시적 product/test_setup 분류가 있을 때만 실패 경로로 돌리며 네이티브 권한 오류는 계속 대기한다. 테스트 역할의 제품 변경은 반려하고 새 구현·테스트·승인이 필요하다. 형식 보완에서는 현재 실제 명령 기록만 재사용한다. 상세 동작은 [AUTONOMOUS_WORKFLOW.md](AUTONOMOUS_WORKFLOW.md)에 기록했다. 그래프 v2에 선택적 automation 필드만 추가했으며 기존 세션 v3는 그대로 읽는다.

## 비용에 따른 재시도

| 상황 | 무료 확인 | 유료·가격 미확인 |
| --- | --- | --- |
| 네트워크·연결·무응답·도구·단계 timeout, 프로세스 오류, 불완전한 응답 | 정상 attempt·시간 한도 안에서 재시도 | 동일 |
| 정상 attempt·단계 복구 시간 소진 | 자동 복구 횟수가 남으면 `RECOVERING` | `PAUSED`; 토큰 사용이 관측되지 않아도 추가 주기를 시작하지 않음 |
| 공급자 잔액·할당량 소진 (`quota_exhausted`, 명시적 quota/credit 오류, HTTP 402) | 제한된 재시도와 추가 복구 허용 | 남은 attempt가 있어도 즉시 `PAUSED` |
| 일시적인 요청 제한·과부하 (일반 429, 503) | 대기 후 정상 한도 내 재시도; 소진 후 무료 추가 복구 | 정상 한도 내 재시도 후 `PAUSED` |
| 무료 추가 복구 횟수 소진 | `PAUSED` | 해당 없음 |
| 자동 복구 재개 시 유료·미확인으로 변경 | 추가 모델 호출 없이 `PAUSED` | 해당 없음 |
| 인증·권한·사용할 수 없는 모델·읽기 전용 역할 위반 | `WAITING_USER` | 동일 |
| 검증 역할의 환경 제약, 필수 검사 `BLOCKED` | `WAITING_USER`, 같은 방문 유지 | 동일 |
| 사용자 중지 / 종료를 확인하지 못한 프로세스 | `STOPPED` / `BLOCKED` | 동일 |

`Upstream request failed: Invalid credential`처럼 공급자 라우팅 계층이 명시된 오류는 실제 HTTP 401/403이 없는 경우 연결 장애로 분류한다. 이 제한된 경우에는 동일한 네이티브 세션에 재접속하지 않고 새 attempt로 복구한다. 일반 `Invalid credential`·`Invalid API key` 및 실제 401/403은 인증 실패로 계속 대기하며, 정상 횟수·시간·무료 추가 복구 한도도 유지한다.

무료 판정은 조회한 **요청 모델 또는 라우터 상품**의 네이티브 `isFree: true`와 유효한 비용 메타데이터에 근거한다. 이름의 `free`, 누락값, 0으로 채워진 기본 비용, 출력·토큰 사용이 없다는 사실만으로 무료를 판정하지 않는다. 캐시·컨텍스트 구간을 포함한 양수 비용은 무료 표시보다 우선하여 유료로 판정하고, 잘못된 비용 값은 미확인으로 처리한다. Kilo Auto Free 내부에서 선택된 실제 모델 ID는 별도로 기록하며, 그 모델의 일반 상품 단가를 라우터 상품의 단가로 대신 사용하지 않는다.

실행·수동 재개·자동 복구 때 같은 CLI와 프로젝트에서 새 목록을 조회한다. 자동 복구 전에 조회 자체가 실패하면 기존 모델 조회 규칙대로 `WAITING_USER`가 된다. 실패한 조회에 이전 무료 캐시를 적용하지 않는다. 시도 기록의 `pricing`에는 판정·근거·조회 시각을 저장한다. 이전 기록의 필드 누락은 미확인으로 처리하며 데이터 버전은 변경하지 않는다. 가격·계정의 실제 청구나 크레딧을 확인하는 기능은 아니며, CLI의 제공 정보가 최신이라는 보장도 없다. 금액 단위의 누적 지출 한도는 아직 구현하지 않았다.

## 성공 조건

| 단계 | 통과 조건 |
| --- | --- |
| 공통 | CLI 종료 코드 0, 정상 종료, 최종 공급자 오류 없음. 마지막 독립 행 `[PHASE_DONE]` (자율 구현의 단일 평문 종료 표식만 제한 정규화). 읽기 전용 역할에서 파일 변경 없음 |
| 계획 | 지정된 개수의 완전한 `OPTION`이 순서대로 존재하고 각 선택지가 모든 REQ ID를 다룸. 승인 필요 설정이면 사용자 승인까지 대기 |
| 구현 | 공통 완료 형식 충족. 구현 완료만으로 테스트 통과를 의미하지 않음 |
| 테스트 | `VERDICT: PASS`, 모든 필수 REQ의 `SATISFIED` 증거, 각 REQ의 `CHECK_COMMAND`와 관측된 성공 검증 명령이 일치. 관측된 미완료·실패 명령이 없어야 함 |
| 검토·최종 승인 | `APPROVED`, 모든 필수 REQ 충족, 현재 구현에 유효한 테스트 PASS 실행 기록 존재. 해당 검토·승인에서 실행한 검사에도 미완료·실패가 없어야 함 |
| 인터넷 조사가 필요한 목표의 계획·검토·승인 | 완료된 검색 이벤트와 `SOURCE`, `VERIFIED_FACT` 또는 `LIMITATION` 행이 추가로 필요 |
| 전체 세션 | `SUCCESS` 종단 도달 + 모든 필수 REQ의 현재 SATISFIED 증거 + 유효한 테스트 PASS 및 실제 성공 명령 기록 + 마지막 최종 승인 역할의 정상 APPROVED와 성공 간선. 미완료 방문·계획/접근 승인 요청이 없어야 함 |

`SUCCESS`는 사용자 정의 그래프에도 같은 전역 조건을 적용한다. 새 실행에서는 최종 승인 노드의 성공 간선만 `SUCCESS`에 연결할 수 있으며, 시작·재진입·중단 경로에서 테스트를 통째로 건너뛰는 그래프는 실행하지 않는다. 불완전한 초안은 계속 저장·편집할 수 있다.

런타임은 종단에서 현재 요구사항 목록과 최종 승인 보고, 요구사항 원장, 현재 테스트 방문의 실제 attempt 명령 기록을 다시 확인한다. `FAIL`, `REJECTED`, `BLOCKED`, 요구사항 누락, 성공 코드 없는 검사, 단순 출력 또는 이전 세션의 근거 없는 PASS는 성공으로 올리지 않는다. 종전 그래프·복구 snapshot이 failure 간선으로 `SUCCESS`에 도착해도 같은 검사를 거친다. 미충족 시 사유를 저장하고 `PAUSED`로 전환하며 자동 추가 호출은 하지 않는다. 수동 재개는 재진입 노드에서 수정·테스트·최종 승인을 다시 수행한다.

기존 세션은 stateVersion 3으로 계속 읽는다. 추가된 내부 attempt 검증 수락 정보가 없는 과거 기록은 현재 검증 증거로 추정하지 않는다. 이미 완료된 과거 실행 기록을 소급 변경하지 않으며, 과거 결과를 새 조건의 통과 증거로 취급하지 않는다. 최종 승인은 `approval` 유형 에이전트의 판정이며, 별도의 사람 최종 승인을 새로 추가한 것은 아니다. 설정된 계획 승인·접근 승인은 계속 지킨다.

구현·테스트 역할은 전경의 단일 검사 명령을 실행한다. 예: `npm test > verification/model-tests.txt 2>&1` (디렉터리 생성과 로그 읽기는 별도 호출). 파이프·종료 상태 래퍼·백그라운드 `&` 명령은 성공 근거로 수락하지 않는다. 검토·최종 승인·계획·중단 분석 역할은 테스트나 서버를 실행하지 않고 현재 테스트 역할의 네이티브 종료 코드와 소스가 일치하는 근거를 확인한다. 재검사가 필요하면 반려하여 쓰기 가능한 경로로 돌려보낸다.

Codex 실행의 로그인 셸은 끄고 Agent Graph를 실행한 Node 디렉터리를 자식 PATH 앞에 고정한다. 기존 sandbox·접근 승인 정책은 유지하며, 테스트 환경 차단은 통과로 바꾸지 않는다.

검증 로그를 읽거나 `echo`로 성공을 출력하는 것은 실행 증거가 아니다. 후속 구현·계획·테스트·중단 방문, 실패·반려, 관측된 파일 변경은 이전 테스트 증거를 무효화한다. 테스트 역할이 테스트를 작성·수정한 경우 마지막 수정 이후의 실제 검사만 인정한다. 같은 방문에서 보고 형식을 보완할 때는 아직 유효한 관측 명령을 재사용할 수 있다. 과거 실패가 있어도 수정 후 새 테스트·최종 승인을 모두 통과하면 성공할 수 있다. 실제 검사를 실행했다는 증거도 검사 범위와 산출물 품질을 보장하지는 않는다.

새 자율 프리셋의 `authoredNodeTests=true`에서는 `npm test`가 등록된 고정 계약에 `nodeTests` 영역 정책도 필수다. 모든 자체 영역의 필수 named case·무결함 대조군·제품 결함 assertion 탐지가 성공해야 한다. skip/todo·import/문법 오류·timeout·제공 인수 검사 호출만으로는 통과하지 않는다. 현재 소스/테스트 해시와 품질 보고서가 일치하고 native suite와 품질 명령 모두 실제 exit 0이어야 한다. 검토·최종 승인도 각 자체 파일과 품질 보고서의 완료된 네이티브 읽기 및 모든 `testScopes` 판단을 요구한다. 누락되면 성공을 차단한다. 기존 필드 없는 그래프의 동작은 유지하며 상세 스키마·상한은 [자체 Node 계약](AUTONOMOUS_WORKFLOW.md#자체-node-테스트의-영역별-계약과-독립-검토)을 따른다.

## 실패·대기·중지 조건

| 판정/상태 | 조건과 다음 동작 |
| --- | --- |
| 테스트 `FAIL` | 명시적 FAIL, 미충족 요구사항 또는 관측된 검사 실패. 설정된 failure 간선으로 이동 |
| 검토·승인 `REJECTED` | 명시적 반려, 미충족 요구사항, 현재 테스트 PASS 증거 없음 또는 해당 방문의 추가 검사 실패·미완료. 환경 제약은 WAITING_USER, 나머지는 failure 간선으로 이동 |
| 불완전한 응답 | 완료 표식·계획·판정·요구사항 증거 형식·실행 증거 누락. 즉시 성공시키지 않고 같은 역할에서 제한된 재시도 |
| `WAITING_USER` | 계획 선택·승인, 프로젝트 밖 경로 승인, 모델 조회·선택·추론 옵션 확인, 인증·권한 해결, 읽기 전용 위반, 인터넷 조사 기능 누락, 테스트 환경 제약 |
| `RECOVERING` | 무료 모델의 복구 가능한 실패가 정상 한도를 소진했고 추가 자동 복구 횟수가 남음 |
| `PAUSED` | 종단의 전역 성공 조건 미충족, 비용 정책에 따른 한도 소진, 무료 추가 복구 한도, 노드 방문·그래프 반복 한도, 중단 분석 완료, 안전하게 자동 재개할 수 없는 워커 소유권 상실 |
| 수렴 정체 | 검토·승인에서 반려되고 요구사항 점수의 개선이 없으면 interrupt 노드로 이동하여 중단 분석 |
| `STOPPED` | 사용자 STOP 또는 정상 서버 종료에 따른 실행·예약 복구 취소 |
| `BLOCKED` | 현재/이전 CLI 프로세스의 종료를 확인할 수 없어 중복 실행을 막음 |
| `FAILED` | 런타임의 처리되지 않은 예외. 활성 프로세스가 남아 있으면 `BLOCKED`를 우선 |

무료 모델이라고 정상 `FAIL`이나 `REJECTED`를 무시하지 않는다. 이는 모델 호출의 전송 실패가 아니라 작업 결과의 판정이므로 그래프의 failure 간선을 따른다. 중단 분석 노드는 정상 attempt 1회로 제한하며 추가 자동 복구를 하지 않는다. 사용자 STOP과 안전 제약은 비용보다 우선한다.

## 기본 한도

| 설정 | 기본값 |
| --- | --- |
| 그래프 완료 반복 | 20회 (`maxIterations`) |
| 노드 방문 | `maxIterations × 노드 수 × 2` |
| 정상 attempt | 한 복구 주기당 3회 |
| 완료 보고 보완 | 추가 1회; 계획·중단 분석 제외. 정상 종료했지만 응답이 불완전한 경우에만 진입 |
| 단계 진행 시간 | 15분; 의미 있는 진행에 따라 연장되지만 절대 복구 시간 이내 |
| 단계 복구 시간 | 주기당 48분 |
| 최초 연결 / 모델 무응답 / 도구 무응답 | 2분 / 5분 / 10분 |
| 일반 재시도 대기 | 5초, 30초에 ±20% 지터 |
| 요청 제한·할당량 재시도 대기 | 기본 30초와 지터, 최대 2분; 남은 복구 시간 이내 |
| 무료 추가 자동 복구 | 최대 3회, 대기 1분 → 5분 → 15분 |

위 시간·횟수는 세션 설정으로 달라질 수 있다. 무료 재시도는 무한 재시도가 아니다. 수동 재개는 같은 방문의 복구 예산을 새로 부여하고 필요하면 그래프 반복 예산을 늘린다. 자동 복구는 저장된 동일한 모델 바인딩을 유지한다.
